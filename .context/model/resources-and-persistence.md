# Resources and Persistence

- Modifiers carry `SkillRankBudgetPolicy` (Included by default, or Excluded), also exposed in ModifierView. Modifier effects accept optional JSON `skillRankBudget: "included" | "excluded"`, rejecting unknown enum values. Only `ResourceManager::modifierTotalForSkillRankBudget` filters excluded entries before resolving and stacking; ordinary totals/Views remain unchanged. The Intelligence rank-budget target uses this evaluation on permanent contributions, while every other consumer retains its ordinary behavior. Source-owned effects recreate this metadata; it is not independent saved character state.

Read this document when changing modifiers, expressions, resource registration, save data, JSON persistence, or aggregate Views.


- The first modifier-domain slice is implemented: modifier enums, stacking metadata, immutable modifier data, UUID generation, normalization, and constructor invariants.
- `BonusType::Generic` represents bonuses without a more specific Pathfinder type. Generic bonuses always stack.
- `ResourceManager` owns the `ModifierSet` of every registered enhanceable resource and keeps live integer targets in a separate normalized registry. It routes modifier additions/removals, calculates totals by resource name, and detects circular target resolution.
- `ResourceManager` supports typed collection resources as its third resource category. A component registers a normalized resource name, its item type, and add/remove callbacks; callers add strongly typed values through the global manager, while an incompatible item type is rejected before dispatch. Collection names remain available through the manager's diagnostic `ResourceManagerView`, which is not exposed by `CharacterSheetView`.
- `Spellcasting` registers per-instance `spellcasting.<castingId>.slots` collections for source-owned `SpellSlotGrant` groups. The sheet owns the casting container and format 27 persists its mutable state, not structural grants; see [spells.md](spells.md) for filters and replacement lifecycle.
- `Movement` registers `movement.grants` for `MovementGrant` values, `movement.adjustments` for `MovementAdjustment` values, and `movement.runAdjustments` for `RunAdjustment` values. `HitPoints` registers `hp.temporary` for `TemporaryHitPointGrant` values; the grant amount is an integer expression resolved through the manager when added. The component remains the owner of its state and rules, while `ResourceManager` only validates and routes collection operations.
- `Movement` has no save root: grants, movement adjustments, and run adjustments are reconstructed by their owning race, class, item, condition, or effect component. `CharacterSheet` does not invent a default racial grant. Hit-point persistence still stores mutable remaining temporary pools. The collection registry is always reconstructed at startup.
- `ResourceManager` also supports accumulated resources backed by `ContributionSet`. Each `Contribution` has an explicit normalized ID and an integer expression; all contributions stack, may resolve to signed values, and can be added or removed independently without modifier types, conditions, or stacking rules. `HitPoints` uses this mechanism for its effective maximum.
- Enhanceable resources may inherit from already registered parent resources. Totals and views combine direct and inherited modifiers before applying stacking rules, deduplicate shared ancestors in multiple-inheritance graphs, and automatically expose category modifiers to resources registered later.
- Skill modifiers use a resource hierarchy rooted at `skill.all`. `skill.craft`, `skill.perform`, `skill.profession`, `skill.knowledge`, and `skill.armorCheckPenalty` inherit from that root. Craft/Perform/Profession specializations inherit from their respective category, Knowledge skills inherit from `skill.knowledge`, armor-check-penalty skills inherit from `skill.armorCheckPenalty`, and every other concrete skill inherits directly from `skill.all`. The armor-check category groups the affected skills for semantic targeting but contains no synthetic penalty modifier; the resolved armor-check penalty is a separate formula term. Consequently global and category modifiers automatically reach existing and future descendants without each skill listing all applicable categories.
- `Skills` also registers the independent semantic resources `skillCheck.str`, `skillCheck.dex`, `skillCheck.con`, `skillCheck.int`, `skillCheck.wis`, and `skillCheck.cha`. Each ability option resolves its ordinary skill-resource hierarchy together with the semantic resource for the ability it currently uses, applying stacking rules once across both sets. Ability replacements therefore automatically gain or lose ability-based skill-check effects. `SkillAbilityOptionView` exposes this combined `ModifierSetView`, while the top-level skill modifier view remains the common skill-only snapshot.
- Integer expressions support literals, registered targets prefixed by `@`, parentheses, unary signs, whitespace, the four basic arithmetic operators with integer division, comparisons, and the logical operators `!`, `&&`, and `||`; logical results are represented as 0 or 1.
- `Requirement` is a reusable expression plus a GUI-facing failure reason. A `Modifier` may own multiple requirements, all of which must resolve to nonzero before it participates in permanent or conditional stacking. Inapplicable modifiers remain in `ModifierView` with their resolved value, active state, and individual requirement results.
- `ModifierSet` calculates permanent totals through `ResourceManager`, applies Pathfinder stacking rules, caps inherent bonuses at +5, subtracts all penalties, excludes conditional modifiers, and rejects negative resolved magnitudes.
- `ModifierView` exposes every modifier field plus its resolved value. `ModifierSetView` contains both `permanentTotal` and the context-effective `total`, effective single-condition deltas grouped by condition, and all resolved modifier snapshots. `ResourceManager::modifierSetView(resource, activeConditions)` resolves all simultaneous conditions with the normal stacking rules while evaluating each expression only once per snapshot.
- `AbilityView` contains the ability type, base value, total value, derived modifier, and its complete `ModifierSetView`; `AbilityScore::toView` resolves the modifier set once per snapshot.
- `AbilitySaveData` contains only the ability type and base value; calculated values and modifier snapshots are rebuilt rather than persisted.
- `ContributionView` contains the ID, expression, and resolved value; `ContributionSetView` adds the accumulated total. Group and manager views expose targeted contributions and deterministically ordered group states.
- Structural modifiers, requirements, contributions, movement grants/adjustments and registered resource sets are reconstructed by their source components. User-created enhancements are now a distinct persisted source: groups save definitions and active flags, not runtime registrations or totals; see [enhancements.md](enhancements.md).
- `CharacterSheetSaveData` is the versioned persistence root and contains ability, hit-point, skill, configured-attack, manual-condition, and inventory source data; armor class, initiative, saving throws, structural strikes/routines, `ResourceManager`, modifiers, contributions, movement, condition definitions, source-controlled condition entries, derived entries, generated item containers, applied effects, and the derived money summary have no direct save data because their state is rebuilt by model components. The current format version is 42, introducing ordered generic enhancement effects and group-level activation/provenance without migrating the obsolete per-entry enhancement schema. Version 41 added a free-text sheet `notes` field (preserved verbatim; older saves default to empty); version 40 added repertoire selections with quota provenance, manual entries and legacy unassigned knowledge; version 39 added sheet-local custom feat definitions and user-owned extra feat slots; version 38 added sheet-local custom spell definitions before source and casting reconstruction; version 37 added full sheet-local custom item definitions before inventory reconstruction; version 36 added user-owned enhancement definitions and active flags; version 35 removed saved language Intelligence entitlement in favor of the live permanent modifier; legacy entitlement is validated then discarded without deleting learned choices. Format 34 added historical prepared-metamagic evaluations and shared source usage balances (see [metamagic.md](metamagic.md)). Format 33 added favored-class selections and per-level rewards (see [favored-classes.md](favored-classes.md)). Format 32 added per-class-level hit die results (missing in older saves). Format 31 added archetype IDs (see [archetypes.md](archetypes.md)). Format 30 added class IDs, levels and choices plus legacy feat-slot migration (see [classes.md](classes.md)). Format 29 added owned granted-spell usage state (see [granted-spells.md](granted-spells.md)) after format 28 added item usage pool state (see [equipment.md](equipment.md)) after format 27 added casting IDs, repertoires and mode-specific state (see [spells.md](spells.md)), and including learned languages and initial Intelligence entitlement (see [languages.md](languages.md)), plus feat selection IDs and choices (see [feats.md](feats.md)); older supported versions without enhancement groups retain their existing unrelated compatibility paths; old saves containing enhancement groups are rejected, not migrated. Versions 8 and 10 through 40 otherwise remain loadable with no inferred pre-version-30 class identities and no pre-version-29 granted-spell usage state, with missing legacy item usage state initialized from definitions and no pre-version-27 casting state, with pre-version-26 learned languages empty and language quotas derived from restored sheet state, with pre-version-25 feats interpreted as empty, pre-version-24 race data interpreted as empty, with pre-version-21 virtual containers interpreted as not contributing to carried weight, pre-version-20 hit-point data interpreted as not already dead unless its restored values immediately reach the death threshold, pre-version-19 inventories interpreted as empty, absent attacks and pre-version-17 conditions interpreted as empty, and version-17 condition entries interpreted as having no parameter. Obsolete modifier, contribution, and movement-group fields in older JSON are ignored, while legacy temporary-hit-point `remainingRounds` is retained as duration metadata. The unreleased version 9 movement-root experiment is intentionally rejected because it could not distinguish structural from user-owned grants.
- The separate `golarion_persistence` library converts `CharacterSheetSaveData` to and from readable JSON through `nlohmann-json`; persistence enum names are stable English identifiers and do not reuse GUI labels.
- `CharacterSheet::save(path)` delegates JSON file writing to the persistence module and reports file opening or writing failures with exceptions.
- `CharacterSheet::load(path)` validates format version and the complete set of six abilities, restores user-owned source values including inventory hierarchy and equipment assignments, and lets model components reconstruct all structural modifiers, contributions, grants, adjustments, generated item containers, and item effects. Armor-class substitutions and limits are not loaded from JSON.
- The previous separate manual modifier/contribution/movement group systems remain removed. `Enhancements` now uses generic effect groups with group-only activation, reverse cleanup and provenance; see [enhancements.md](enhancements.md).
- `ResourceManagerView` remains a diagnostic snapshot used by focused manager and resource-hierarchy tests. It exposes registered targets, collections, and enhanceable resources with their resolved modifiers, but is deliberately not part of the GUI-facing sheet snapshot.
- `CharacterSheetView` aggregates canonical and granted actions, reminders, abilities, strikes, structural attack routines, configured attacks, hit points, initiative, armor class, saving throws, skills, resolved movement, inventory/equipment, and the condition-manager snapshot for the GUI. It also exposes race, feats, languages, granted spells, classes and the aggregate Spellcastings View (casting identity/source/mode/repertoire plus typed prepared, spontaneous or flexible state).
