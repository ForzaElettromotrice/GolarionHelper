# Races

Read this document when working on the race catalog, runtime race configuration, persistence, or race Views.

- `RaceDefinition` is declarative catalog data and has no per-character runtime behavior yet. A race definition contains its stable ID, Italian name, and ordered racial qualities, standard features, and alternate features. Every racial element contains a stable ID, Italian name and description, its unconditional typed effects, optional exact-count choices, and the IDs of any baseline elements it replaces. Every choice option has a semantic ID, Italian name, and its own effects, so rules such as “+2 to one chosen ability” are represented by six ordinary options rather than manager-specific branching. `raceDefinitionFromJson()` parses this complete structure and rejects duplicate element/effect/choice/option IDs, impossible selection counts, replacement declarations on baseline elements, and alternate features that reference unknown baseline elements.
- `RaceDefinitionManager` is a process-wide immutable singleton analogous to `ItemDefinitionManager`. CMake embeds `core/sheet/resources/races.json` into the backend library, so catalog lookup is independent from the current working directory. The first `get()` atomically parses and validates the whole catalog into a `std::map`; later normalized lookups return the same stable `const RaceDefinition&`, and missing IDs fail explicitly. The catalog contains the standard profiles of all seven core races: `human`, `elf`, `gnome`, `halfling`, `halfElf`, `halfOrc`, and `dwarf`. Umano also retains Doppia Dote with its two-ability choice and three declared replacements; the other races currently have no alternate features. The manager owns definitions only; each sheet's `Race` resolves its selected definition from it.
- `Race` is the mutable per-character runtime configurator owned by `CharacterSheet`. The sheet exposes narrowly scoped forwarding APIs to select/clear the race, select/remove alternate racial features, and complete racial choices; `CharacterSheetView` includes the resulting `RaceView`, while the race itself applies every active effect through the sheet's shared `ResourceManager`. It starts empty and supports selecting or clearing one catalog race, selecting/removing compatible alternate features, and setting an exact complete option list for a choice on an active element. Alternate features automatically suppress every baseline quality or standard feature named by `replaces`; two selected alternatives may not replace the same baseline element. Choice IDs and option IDs are normalized and validated, with exact cardinality, no duplicates, and no hidden mutation of inactive elements. Selections belonging to inactive replaced elements are retained, so removing an alternate feature restores the previous baseline choice; selections on removed alternatives likewise resume if that alternative is selected again.
- `RaceSaveData` persists the selected race definition ID, the selected alternate-feature IDs, and every completed racial choice as its element ID, choice ID, and canonical option IDs. Choices on currently inactive/replaced elements are deliberately retained in the save, so their prior configuration resumes if the replacing alternate feature is later removed. `Race::load()` validates the complete saved configuration against the current definition catalog before transitioning effects, and `CharacterSheet`/JSON save format 24 include this data. Older supported saves load with no selected race.
- When a race is selected, `Race` compiles every possible direct and choice-owned effect exactly once with stable IDs derived from race, element, choice, option, and effect identity. Configuration changes calculate the desired active effects, retain unchanged applications, remove obsolete cleanups in reverse order, and apply only additions in definition order. A failed addition removes newly applied effects and restores every old removed effect before leaving the previous configuration unchanged. Clearing or destroying `Race` cleans every remaining effect. An active element with an unresolved choice still applies its unconditional effects but none of that choice's option effects.
- `RaceView` contains only the optional selected race summary and the currently active racial elements. Each element carries its Italian name and description, completed choice selections with their chosen option IDs/names, and unresolved choices with prompt, exact selection count, and all available option IDs/names. Replaced/inactive elements and the full alternate-feature catalog are deliberately absent; catalog browsing will be exposed separately when needed. A runtime configuration is complete precisely when every active element has an empty `missingChoices` list.

## Core Catalog Coverage

- All seven profiles register biped carrying type, racial base size, land movement, and fixed ability modifiers or the exact one-ability choice. Size consequences are supplied by `SizeManager`, never duplicated in race modifiers. Dwarf movement uses four 1.5-metre units and is unaffected by armor and load; ordinary Small races use four units, and the other Medium races use six.
- Permanent bonuses cover Keen Senses, Halfling Luck, Sure-Footed, and Intimidating. Situational modifiers cover enchantment/illusion/fear saves, magic-item identification, Hatred, Defensive Training, Stability, Greed, and Stonecunning. Conditions are explicit Italian contexts supplied by callers, not inferred from rule descriptions. Dwarf Hardy is one modifier for the union of poison, spell, and spell-like-ability contexts, preventing double application to overlapping effects. Defensive Training targets `armorClass.reflexive` and requires a giant opponent while retaining the Dexterity bonus; it is absent from flat-footed AC. The current sheet AC View still exposes situational previews rather than selecting encounter contexts.
- Reminders preserve unsupported creature types/subtypes and racial eligibility, languages, low-light vision/darkvision, weapon familiarity/proficiency, magical-sleep immunity, caster-level checks against spell resistance, Gnome Magic, Gnome Obsessive, Half-Elf Adaptability/Multitalented, Half-Orc Orc Ferocity, Human Skilled/Bonus Feat, and Stonecunning's automatic nearby check. The immunity endpoint now has a declarative effect; migrating the existing racial reminder to it is catalog work. Obsessive needs an open character-owned specialization choice; a fixed list of catalog options would exclude valid custom Craft/Profession specializations.
- `race_test` covers every added profile's application, size consequences, movement flags, situational totals, choice persistence, direct race changes, and effect cleanup. Core definitions add no new runtime mechanics or save-format version.
