# Declarative Content

Read this document when changing shared declarative effects or feat definitions.

- `EffectDefinition` is a reusable, type-safe `std::variant` shared by races, items, and future class, feat, or other declarative sources. Its initial alternatives describe modifiers, accumulated contributions, the race-owned size base, movement grants, the race-owned carrying body type, and GUI reminders. Every effect has a source-local stable ID. The stateless `compileEffect` function receives one definition plus an `EffectContext` containing the globally stable instance ID and GUI source derived by its owner; it returns an apply callback whose only argument is `ResourceManager`, and applying it returns the exact cleanup callback. All six current alternatives are translated through their existing resource entry points. `effectDefinitionFromJson()` parses the same alternatives from stable English JSON type names, while non-automatable rule text is represented as a reminder rather than an opaque native callback. Further typed collection alternatives, definition managers, and source-owned cleanup lifecycles remain separate later steps.
- `FeatDefinition` is the declarative, frontend-independent description of a feat. It carries a stable ID, Italian name and complete rules text, open semantic type IDs, requirements, unconditional typed effects, and optional exact-count choices. Each requirement contains Italian display text plus an optional machine-checkable expression; requirements without an expression remain explicitly manual instead of being falsely treated as automatically satisfied. Choice options may own their own requirements and effects, allowing selections such as a weapon to validate and modify a different semantic resource. Repeatability and separate Normal/Special fields are deliberately not modeled: those rules remain in the complete description. No feat catalog, JSON parser, slot grants, runtime manager, View, or persistence exists yet.
