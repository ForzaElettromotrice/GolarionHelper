# Desktop Frontend

Read before working on the application window, adding panels or wiring controllers. The selected stack is Qt 6 / Qt Quick / QML, initially targeting Windows and Linux. Phone layouts and packaging are deferred.

## Desktop application

The reusable `Golarion.Sheet` module is organized under `frontend/sheet/`: `SheetView.qml` is the entry point, `panels/` holds subsystem views, `components/` holds smaller UI elements, `helpers/` holds shared JavaScript and `assets/` holds graphics and attribution. CMake resource aliases preserve the module's QML types and relative resource URLs.

The desktop shell keeps `main.cpp` and `Main.qml` in `frontend/app/`, with feature pages under `pages/`, shared session UI under `components/`, C++ controllers under `controllers/` and their tests under `tests/`. The sample preview executable and its fixtures have been removed; older verification notes below describe the former preview.

SheetController is a C++-owned QObject registered as an uncreatable QML type and injected into Main.qml independently of SessionController. After QML loads, Qt Concurrent preloads the shared class, class-option and archetype catalog. The sheet list remains available during warm-up; a pending file request shows a loading state until the catalog is ready. The controller then creates or reconstructs the CharacterSheet on the GUI thread before emitting sheetOpened. Other catalogs are not preloaded.

Schede manages character files under the application's local data directory in `sheets/`, alongside `campaigns/`. Nuova scheda asks for a name; creation and import use a numbered suffix on collisions. Importa scheda validates the file and opens a private copy; Esporta writes an independent JSON copy to the chosen destination. QSettings tracks the local library separately, ignoring the old file list without migrating or deleting files. Removing a row does not delete its file. Accepted edits save to the managed copy with QSaveFile and the existing model JSON codec.

`frontend/app/` defines the `Golarion.App` QML module and the `golarion_helper` executable. The main window uses Qt Quick Controls Basic with a light, neutral palette. The home page stacks Sessioni and Schede on the left and scrolls when the window is short. The toolbar's right-hand field starts at Daniele and is directly editable. Its value is shared across pages for the current application run.

Sessioni opens a scrollable Campagne list. + Aggiungi offers Crea campagna and Unisciti con IP e codice. The creation form saves a name locally and adds a Da avviare row. Opening a hosted campaign shows its copyable invitation code next to the top-right Avvia hosting control and a numeric port field (default 42500) in the page. At narrow widths the actions use a second toolbar row. Avvio in corso disables repeat starts and navigation while the controller starts the host in a background task. A successful start replaces Avvia hosting with Ferma hosting and shows the copyable endpoint. Tailscale appears first when available and other endpoints are in a dropdown. A failed start leaves the campaign open for retry. Stopping returns to Campagne. See [desktop hosting](game-management.md#desktop-hosted-campaigns) for storage and lifecycle.

The join form accepts numeric IPv4 with an optional port (default 42500) and the five-character session code. Desktop hosts reuse the same saved code across starts. A joined row opens the form with its last address and code so they can be updated when needed. Errors remain beside the form with the entered values available for retry. Successful admission opens the session page with its title and Disconnetti in the right-hand corner. Disconnect or loss of connection returns to Campagne. See [client sessions](session-client.md#desktop-campaigns) for title lookup, persistence and credential behavior.

The Partecipanti panel appears on the right of active host and client session pages and stacks below the session details in narrow windows. It displays the host-supplied displayName as plain text and labels the host with Host and the local participant with Tu. The home name field is stored in the local Qt profile settings. The controller passes that name to host startup and client join/resume, validates it with the shared backend rules and reports invalid names in Italian. Presence refreshes through `Session::toView()`. The controller test covers host/client names, admission, reconnect and departure.

Selectable participant rows open the Permessi dialog. The host and delegates can edit other players, and the Gestire i permessi checkbox is editable only by the host. The dialog loads current permissions asynchronously, keeps checkbox edits in a local draft and applies the changed flags together on Salva. Annulla discards the draft. On a save failure the dialog keeps the draft and shows the error. The ordinary labels Permission1 through Permission5 remain provisional. See [permission commands](session-permission-commands.md).

Configure the [root build](development.md#required-project-build-entry-point) with `GOLARION_TARGET=golarion_helper` and a Qt 6.9+ kit matching the compiler, then run `cmake --build build --target golarion_helper`. With Ninja and Qt's default output directories, the executable is under `build/frontend/` on Windows and `build/frontend/app/` on Linux. On Windows, make the chosen Qt kit's `bin` directory available on PATH.

A previous revision was verified on Windows with Qt 6.8.3 and MSVC; the current frontend requires Qt 6.9+ for QML ContextMenu. `golarion_session_controller_test` exercises offline creation and reopening, pending navigation guards, port conflicts, a second window opening the same archive, title publication, and identity-preserving resume after stopping and reopening the host. The join and disconnect tests remain in the same suite. The QML interaction smoke test checks the starting state, endpoint selection, and which values the copy controls submit.

The Qt controller adapts the hosted and joined campaign models and the live `Session::toView()` snapshot to QML. Campaign rows expose a stable ID, name and invitation code. Joined rows also expose their address. The controller writes campaign data at the JSON boundary.

Campaign rows have a separate removal button. For hosted campaigns, the modal shows the name and saved invitation code and requires the exact name in the confirmation field to enable **Sposta nel Cestino**. Clicking the name copies it to the clipboard and focuses the confirmation field for pasting. For joined campaigns, one confirmation removes the local connection record and its token. The dialog gives initial focus to **Annulla** and supports Escape. The controller receives the stable campaign ID. Failed operations show an error while keeping the row available.

## Composition and ownership

- Build independent subsystem panels first, then aggregate them into larger screens. No final tab grouping is fixed.
- A panel accepts presentation data and emits requested changes. It must not know `CharacterSheet`, the controller, a session, the main window or persistence.
- Qt-specific code stays outside `core/`. A future controller will expose snapshots and operations through an access interface; local and game-session adapters can implement that interface without changing QML components. Operations may be delayed or rejected. This boundary is a design decision, not implemented infrastructure yet.
- Existing C++ `View` structs remain presentation snapshots, not automatically observable Qt objects. The future adapter must map values/enums and publish changes explicitly.

## Implemented panels

Saving throws and skill rows show one situational card per conditional total underneath the corresponding score, outside the info disclosure. The value is the rules engine's stacking-aware delta for that circumstance, not a change to the displayed current score. Skills use the conditional totals for their ability options, showing distinct adjustments in option order. Zero-only cases are hidden; mixed values use a dash for zero.

Generated attacks show compact situational lines immediately below the relevant attack, damage, or confirmation value, omitting zero values. A situational confirmation delta makes the confirmation value visible even when its current value equals the attack bonus.

Combat maneuvers reuse the saving-throw situational cards, grouping BMC and DMC deltas by condition below each maneuver.

It matches the Combat tab's dark full-width headings and responsive columns. The local controller dispatches standard and extra feat selection/removal, including required feat choices, learned and manual languages, and authoritative reminders. The standalone previews retain their original fixture headings.

The composed Incantesimi preview uses the existing class-casting and granted-spell panels at full width, with granted spells below class casting. The composed tab and standalone modes instantiate the same sample components and handlers independently instead of moving panels out of a hidden view. The desktop tab uses authoritative repertoire, slots, metamagic and granted-spell snapshots. Local commands prepare, cast, clear, reset and learn through CharacterSheet. Eligibility probes use the same rules and validate usage budgets without consuming resources. Casts retain exported effects and target limits without applying effects to recipients.

The live Home shows only active conditions at their current stage; it lists separate bleeding entries and summarizes negative levels by effective count.

The standalone preview opens on the full Home layout using read-only fixtures for damage reductions, immunities, and every energy palette in both resistances and vulnerabilities. Resistances and vulnerabilities share the palette for their energy but retain distinct shapes and symbols. Damage reduction and non-energy immunity use the sheet’s neutral gray. Damage reduction and energy resistance use compact shields with the same heraldic outline as armor class. Both defense rows (tags and shields) wrap based on available width, without a fixed item cap. The sample data does not affect live sheets.

The enhancements editor starts with no resource selected and determines the effect family from the selected resource. The live picker shows the raw IDs from the two CharacterSheet resource lists. Contributions go directly to the expression; modifier resources offer bonus or penalty and a bonus type where applicable. The resource search matches substrings of IDs and display names, ignoring case. EnhancementsPanel displays the EnhancementsView groups with optional descriptions and an authoritative activation switch per group. GrantedSpellsPanel lists CharacterSheetView.grantedSpells separately from class casting. It shows name, source, remaining uses or charges, and charge cost per cast. SpellcastingsPanel selects casting instances by ID and shows a selector only when more than one is present. The repertoire on the left uses supplied name and class-specific level lookups; entries with an unknown level appear last. The right pane shows one slot card per View entry, grouped by spell level. Narrow layouts stack the panes. Flexible casting uses slotGroups, not preparationGroups.

The repertoire is followed by the active casting's known metamagic grants from state.metamagic. Presentation metadata keyed by type supplies localized names and standard level adjustments; a grant may supply its own adjustment. Unknown or variable adjustments are shown as variable.

The repertoire + opens a searchable picker over the host-supplied spell catalog. Positive repertoire quota counts produce source/level choices; candidates match the exact class-list level and any quota filter, and exclude previously quota-selected spells. Prepared and flexible casters can also use a separate manual option when the snapshot authorizes it. Spontaneous casters never use manual addition. Requests distinguish manual additions from quota selections. The synthetic preview demonstrates exhausting a Bard quota.

A full-list grant adds catalog spells to the repertoire automatically when at least one slot has sufficient level and a compatible filter, regardless of current slot occupancy. Explicit repertoire IDs are preserved and deduplicated. A full-list caster does not see a redundant manual add action. The Paladino preview demonstrates a level-1 list with higher-level spells hidden.

Slots with an explicit spell filter display a Limited tag even when occupied. The info toggle appears beside the tag on slot hover or keyboard focus, without shifting the row. The shared details panel lists the allowed spells or explains that an empty filter allows none. The source remains available in the tooltip.

Spontaneous casting drags a repertoire spell onto a compatible free casting slot. The panel requests immediate casting unless valid casting metamagic choices open the shared picker. The request carries casting ID, slot ID, spell ID and metamagic, without preparing the spell or associating it with the slot afterward. Azzera slot clears consumed slots in the selected casting without changing its repertoire or metamagic uses. The Bard preview demonstrates Sonno with optional Incantesimi Immobili in a level-2 slot.

Flexible casting shows three columns (Repertorio, Preparazioni, Slot di lancio) in wide layouts and stacks them in narrow layouts. The two drag operations reuse the conditional metamagic picker, supplied with independent phase-specific eligibility and combination options by the host.
