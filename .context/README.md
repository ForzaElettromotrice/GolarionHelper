# GolarionHelper Context

## Project Goal

Build a local-first native desktop tabletop role-playing application in C++, expanding toward a virtual tabletop in the style of Roll20. The implemented rules engine remains Pathfinder 1e; support for another ruleset is not implied.

## Current State

- Character-sheet backend is complete within the agreed scope; project/library version is `1.1.0`, adding generic enhancement groups and spell-effect export. Applying exported effects belongs to the game session's sheet manager. Free-text `notes` is exposed through `setNotes`, Data and View; save format is `42`, with empty notes for older saves. See the [Data/View audit and release scope](model/backend-v1.md). Complete datasets, frontend/full FFI and `core/play` completion remain separate.

- Pending-choice reporting is implemented across sheet subsystems. Class/racial choices declare whether they block advancement; feat selection remains atomic. Reports are derived and are not persisted. Blocking entries now prevent +1 class-level advancement. See [`model/pending-choices.md`](model/pending-choices.md).

- Custom feats use a sheet-local `FeatCatalog`. User-owned extra feat slots ignore prerequisites but retain valid choices and repeatability; creation/removal, Data/View and format-39 persistence are implemented. See [`model/feats.md`](model/feats.md).

- Sheet-local custom spells now use `SpellCatalog`, shared by all casting modes and granted spells. Format 38 persists full definitions before source reconstruction; Data/View expose them. Registration does not grant casting or populate repertoires; see [`model/spells.md`](model/spells.md).

- Sheet-local custom item definitions now share the embedded item/effect JSON schema and the ordinary inventory runtime. Format 37 saves definitions before reconstructing instances, effects, choices and charges; see [`model/equipment.md`](model/equipment.md).

- Cohesive public C++ parameters now use domain Definitions for modifiers, spell preparation/consumption, class choices, attack/specialization creation and enhancements. The Definition refactor preserves persistence; custom feat definitions and extra slots were added in format 39; the current format is 42; see [`model/operation-definitions.md`](model/operation-definitions.md).

- User-created `Enhancements` groups now support shared `EffectDefinition` entries with group-only activation, optional description/provenance, ordered application/reverse cleanup and format-42 persistence. Editing entries requires an inactive group; the old per-entry save schema is rejected without migration. Custom spell definitions are now supported separately; see [`model/enhancements.md`](model/enhancements.md).

- `main` is the default development and GitHub branch. The game-host feature branch is `feat/game-host`; the previous `master` branch is retained separately.
- The C++20 backend, persistence, Views, and a minimal opaque-handle C API are in place; frontend work remains deferred.
- `core/` groups backend modules. The character-sheet engine lives in `core/sheet/`. The independent `core/play/` C++20 module provides Session, its managers, TCP hosting, JSON admission/authenticated dispatch, identity persistence, and a console host. Game/network and their client/tests are removed. Client-side ProtocolManager, concrete role/sheet commands, user-list events, sheet bindings, full game persistence, and frontend remain future work; see `game-management.md`. In-app chat/voice/video are outside scope.
- `golarion::play::Session` is a container/facade for its registry/managers. Hosting and connection methods delegate to ProtocolManager, which owns synchronized state, private TCP hosting, and admission. RoleManager synchronizes role operations and exposes staged registration for persistence. `getUserId` exists only on ProtocolManager; no connection/hosting features are published through ResourceManager. See `session-admission.md`.
- The session ResourceManager lives in `core/play/` and implements typed function registration, invocation, and removal, with focused C++20 tests passing. Each Session has an independent registry. See `architecture.md` for the API and lifetime rules; the sheet-specific `golarion::ResourceManager` retains its existing responsibilities.
- ProtocolManager implements one registry/dispatch path for every command, including built-in join/resume with minimum `Any`. `Any` is a nonassignable access threshold below Spectator; live pending peers have optional empty identity, while stale/unknown connections remain rejected. Every success uses `request.accepted` / `payload.result`. Local/remote execution is serialized and permissions are checked through RoleManager. Stop discards queued network requests, including those waiting for execution, and lets an already started request finish. See `protocol-manager.md` and `session-commands.md`. Native verification and host-process restart checks pass on Windows; see `development.md` for the latest coverage.
- SessionCode generation/comparison is implemented: five uppercase ASCII alphanumeric characters, lowercase accepted, generated once per ProtocolManager and exposed through Session for console display. Shared host-registry uniqueness and persistence are explicitly deferred; see `session-protocol.md`.
- The private codec uses generic JSON v2 over TCP. The host console takes IP/port and an optional identity archive (default `session-identities.json`), creating/loading it before listening; its main thread waits for Ctrl+C while ProtocolManager handles networking. There is no client executable yet. See `session-protocol.md` and `development.md`.
- Declarative `EffectDefinition` values and `compileEffect` are shared by source subsystems. The six-point backend audit now has typed JSON bridges for structural/casting endpoints and feat prerequisite alternatives, recursive class-level binding, selective CA retention, bounded movement bonuses and sheet inventory/casting operations. See [`model/effect-endpoints.md`](model/effect-endpoints.md) for coverage and boundaries.
- `CharacterSheet` owns `Classes`, with enum-based level advancement and a computed total (initially 0). Class definitions/runtime support level-gated choices, replacements and base contributions; format 33 persists class identity, levels, player-entered hit dice, archetype IDs, favored-class selections and feature choices before reconstructing dependent state. Class Views are exposed by the sheet. A separate [archetype catalog](model/archetype-catalog.md) now loads 661 reviewed definitions; 103 of 764 reviewed source entries remain pending and nonselectable. `ClassDefinitionManager` loads 44 playable Golarion classes through strict JSON parsing, including full base tables and 25 casting progressions. Many privilege choices remain marked manual; see [class catalog coverage](model/class-catalog.md). See [`model/classes.md`](model/classes.md).
- `RaceDefinitionManager` embeds all 63 races listed by Golarion, with 278 alternate entries and 485 class-filtered favored options. `Race` applies effects, manages replacements/choices, persists configuration and exposes `RaceView`. Unsupported portions retain marked reminders; catalog presence does not imply full automation. Read [race catalog coverage](model/race-catalog.md) for sources and group-specific boundaries.
- `FeatDefinitionManager` loads immutable feat definitions from embedded JSON. `CharacterSheet` owns `Feats` with source-owned slots, prerequisite alternatives/exemptions, repeatability, choice-matched dependencies, and stable-state activation. Sheet changes automatically recheck prerequisites; manual text requirements are informational. Format 25 persists selection IDs and choices; Views expose distinct acquisitions and slots, with slot availability independent from feat activation. Source withdrawal preserves selected feats and choices, including across save/load. The embedded catalog contains 1648 ordinary Golarion feats; 46 provide mechanical effects. Structured numeric/dependency checks, manual prerequisite markers and conservative repetition boundaries are documented in [feat catalog coverage](model/feat-catalog.md).
- Informational special defenses cover the planned categories, including the locally implemented energy vulnerabilities.
- Attack routines now accept source-owned conditional hand-usage permissions without reclassifying weapons. Permissions can be scoped to a strike/routine/slot and are exposed in candidate Views. The shared `handUsagePermission` effect now parses and compiles these grants with reversible cleanup; concrete providers and contextual penalty rules remain separate; see [`model/combat.md`](model/combat.md).
- Item definitions support named usage pools with capacity only; instances own independent remaining counts. `consume`, `refill` and capped `restore` do not interpret recovery rules, which belong in description text. `spellGrant` effects connect item reserves to granted spells without resetting them on equip. See [`model/equipment.md`](model/equipment.md).
- `CharacterSheet` owns `GrantedSpells` through `spells.granted`: single-spell grants support own uses, at-will, constant and shared-pool usage, source cleanup, Data/View and format-29 persistence. Actual cast resolution remains separate. See [`model/granted-spells.md`](model/granted-spells.md).
- `SpellDefinition` ports the typed Java schema from `master`: closed enums, separate class/domain/bloodline level maps, structured casting/component/save metadata, descriptive text, and explicit validation. `SpellDefinitionManager` loads an embedded JSON catalog through strict enum parsing and validation; the catalog contains 2158 ordinary Golarion spells across all levels; 81 definitions export supported mechanics. Three incomplete Golarion entries remain explicitly pending; mythic and legacy 3.5 entries are excluded. Manual portions retain the agreed marker. See [spell catalog coverage](model/spell-catalog.md). `CharacterSheet` owns `Spellcastings`: its `spellcastings` endpoint creates/removes independent prepared, spontaneous or flexible instances using source-chosen IDs. Spell definitions also accept shared declarative effects, exported as caster-frozen copies by consumption; targeting/application and concrete casting sources remain unimplemented. The shared `spellcastingGrant` effect now creates/removes prepared, spontaneous or flexible casting instances; `spellSlotGrant` now grants multi-level casting or flexible preparation slots with a shared optional spell filter and an explicit target casting ID. Concrete progression tables remain source-owned.
- `Languages` distinguishes source grants from learned selections, persists the latter in format 26, and reports unused/exceeded quotas. `languageGrant` is supported by the effect parser/compiler. Intelligence entitlement is computed from `max(0, intPermanentMod)`; format 35 saves only learned choices and ignores the validated legacy manual quota. The `languageOptions` effect now registers per-origin selectable lists through `languages.options`; their union is enforced by `add`, and without lists no new language can be learned. Lists appear in Views and are reconstructed from sources, not saved. Reviewed races register starting/Intelligence languages and the shared 82-language nonsecret Linguistics list; explicitly permitted secret languages remain local racial exceptions.

No historical prerequisite snapshots are planned; replacement selections use current state.

Player-entered hit dice and the class-driven skill-rank budget endpoint are implemented with persistence and Views. Single-spell grants and item bindings are implemented; next steps are concrete catalog providers and cast resolution, one slice at a time.
